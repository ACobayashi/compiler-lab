\begin{abstract}
本报告围绕语言处理系统的完整工作过程以及 SysY 程序到中间代码、目标代码的等价实现开展实验。小题1由两名成员分别独立完成，以 GCC 或 LLVM/Clang 为研究对象，通过预处理、编译器内部阶段、汇编和链接等实际输出，分析各阶段的输入、输出及其与源程序的对应关系，并进一步通过优化等级、调试信息、静态链接和自动并行化等编译参数进行扩展探索。小题2采用同一份 SysY 示例程序作为语义基准，程序覆盖数组、赋值、算术与取模运算、条件分支、循环、函数和运行时输入输出等语言特性；两名成员分别完成 LLVM IR 与 RISC-V 两种等价实现，并通过链接 SysY 运行时库和统一测试数据验证目标程序的正确性。当前稿已完整整理成员A的小题1与 RISC-V 实验，成员B的小题1及 LLVM IR 实验位置已预留，待实验完成后补充并进行最终联合校对。
\end{abstract}

\noindent\textbf{关键词：} GCC；编译流程；SysY；LLVM IR；RISC-V；运行时库

\section{引言}
高级语言程序从源代码变为可执行程序，并不是由单一阶段一次完成，而是由预处理器、编译器、汇编器和链接器等多个组成部分协同工作。进一步观察编译器内部，还可以划分为词法分析、语法分析、语义分析、中间代码生成、代码优化和目标代码生成等阶段。若只观察最终执行结果，难以直接理解宏、类型、控制流、函数调用、符号和库依赖在这些阶段中如何变化，因此本实验利用编译工具提供的命令行选项保存各阶段产物，并将其与源程序逐项对照。

在此基础上，小题2进一步从“观察编译器输出”转向“直接编写中间表示和目标汇编”。两名成员共同设计一份 SysY 示例程序，再分别用 LLVM IR 和 RISC-V 汇编实现相同语义，并链接 SysY 运行时库形成目标程序。通过统一测试数据比较两种实现的输出，可从基本块、条件跳转、函数调用、数组地址计算、调用约定和运行时库接口等角度理解源语言语义向中间表示和目标代码的映射关系。

\section{实验环境与总体方法}
成员A的小题1实验在 WSL2 Ubuntu 22.04 环境中完成，主要使用 GCC 11.4.0，并在词法分析阶段使用 Clang 14 输出 token 序列，目标平台为 x86-64。RISC-V 部分使用课程提供的 RISC-V 交叉工具链与 QEMU，目标为 RV64，并链接课程提供的 SysY RISC-V 运行时库。成员B的小题1实验环境和 LLVM IR 部分所使用的 LLVM/Clang 版本由成员B完成实验后补入相应章节。

总体方法分为两条主线。第一条主线以一份简单 C/C++ 程序为研究对象，利用编译器选项观察预处理文件、token、GCC tree、CFG、RTL、汇编文件、目标文件和最终可执行文件，并通过参数对照观察不同设置对各阶段输出的影响。第二条主线以同一份 SysY 程序为语义基准，由两名成员分别手工实现 LLVM IR 与 RISC-V 版本，完成编译/汇编、链接和多组输入验证，检查两种实现是否与 SysY 源程序保持等价。
