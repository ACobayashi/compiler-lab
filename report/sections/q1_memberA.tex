\subsection{成员A：C++/GCC 宏与编译流程实验}

本部分由成员A负责。实验使用一个 C++ 阶乘程序，按照 GCC 的预处理、编译、汇编和链接流程依次生成各阶段结果。源程序中加入自定义头文件、普通宏、带参宏、条件编译、全局变量、全局常量、函数、条件分支和循环，用于观察这些内容经过各编译阶段后的变化。实验环境为 WSL2 下的 Ubuntu 22.04，g++ 版本为 11.4.0，目标平台为 x86-64，中间文件统一保存在 \texttt{output} 目录中。

\subsubsection{编译器内部阶段}

这一部分分别从词法分析、语法分析、语义分析、中间代码生成、代码优化和代码生成几个阶段分析编译结果。GCC 的 tree、CFG 和 RTL 用于观察主要的中间表示，词法分析部分使用 Clang 输出 token 序列作为补充。

\paragraph{词法分析}

使用 Clang 输出 \texttt{main.cpp} 的 token 序列。为了减少标准头文件产生的大量输出，只保留来源于 \texttt{main.cpp} 的 token：

\begin{lstlisting}[language=bash]
clang++ -Xclang -dump-tokens -fsyntax-only main.cpp 2>&1 \
  | grep "main.cpp:" | head -n 60
\end{lstlisting}

结果中包含 \texttt{using}、\texttt{int}、\texttt{const}、\texttt{for} 等关键字，\texttt{times}、\texttt{factorial} 等标识符，以及数值常量和运算符。宏展开生成的 token 还保留了来自 \texttt{test.h} 的位置信息，如图~\ref{fig:q1-token} 所示。

\labfigure{figures/memberA/q1/lexical_1.png}{Clang 输出的 main.cpp 词法 token 序列}{fig:q1-token}

\paragraph{代码优化}

使用同一个预处理文件分别生成 \texttt{-O0} 和 \texttt{-O2} 两个版本的汇编：

\begin{lstlisting}[language=bash]

g++ -O2 -S -masm=att output/main.ii -o output/main_O2.s
\end{lstlisting}

图~\ref{fig:q1-o0o2} 对比了两个版本的文件大小和行数。\texttt{-O0} 版本约 3.6 KB、193 行，\texttt{-O2} 版本约 4.2 KB、222 行，因此汇编文本变长并不代表优化效果变差。

\labfigure{figures/memberA/q1/image18.png}{-O0 与 -O2 汇编文件比较}{fig:q1-o0o2}

再单独比较两个版本中的 \texttt{factorial} 函数。\texttt{-O2} 版本主要用寄存器保存循环变量和中间结果，循环体主要由 \texttt{imulq}、\texttt{addq}、\texttt{cmpq} 和 \texttt{jne} 等指令组成，\texttt{times++} 也变为直接对内存加一。与 \texttt{-O0} 版本相比，\texttt{-O2} 版本减少了栈内存读写。图~\ref{fig:q1-o2fact} 为 \texttt{-O2} 下的 \texttt{factorial} 汇编。

\labfigure{figures/memberA/q1/image19.png}{-O2 下 factorial 函数的汇编结果}{fig:q1-o2fact}

\paragraph{自动并行化与优化报告}

使用 \texttt{-O3 -ftree-parallelize-loops=4} 尝试对循环进行自动并行化，同时生成优化报告。图~\ref{fig:q1-parallel} 中，GCC 对阶乘循环给出了 \texttt{couldn't vectorize loop} 和 \texttt{not vectorized}，生成的汇编中也没有出现 GOMP/parallel 运行时调用。

\texttt{factorial} 中的 \texttt{result = mul(result,i)} 使用上一轮循环得到的 \texttt{result}，各次迭代之间存在数据依赖，因此这次编译没有将该循环转换为并行执行形式。

\subsubsection{本小题小结}

预处理结果中，\texttt{N} 被替换为 \texttt{20}，\texttt{mul(result,i)} 被展开为乘法表达式；定义 \texttt{DEBUG} 后，\texttt{debug(n)} 生成输出语句。编译阶段得到的 tree、CFG 和 RTL 分别包含程序的树结构、基本块关系以及更接近机器层的表示。目标文件符号表中，函数、零初始化全局变量和外部符号分别出现了 \texttt{T}、\texttt{B} 和 \texttt{U} 标记。

不同编译参数的结果也存在明显差异。\texttt{-O2} 版本的 \texttt{factorial} 比 \texttt{-O0} 版本减少了栈内存读写；加入 \texttt{-g} 后，文件中增加了调试相关段；加入 \texttt{-fno-omit-frame-pointer} 后，汇编中保留了 \texttt{\%rbp} 栈帧。静态链接版本约为 2.3 MB，而动态链接版本约为 17 KB，但两种程序输入 \texttt{5} 时都输出 \texttt{120} 和 \texttt{1}。阶乘循环存在前后迭代的数据依赖，优化报告中显示该循环没有被向量化，也没有生成 GOMP 并行运行时调用。
